The settings files a real install writes, captured off machines the bootstrap
stages really installed, so that settings-template.ts is held against real
output rather than against a copy somebody typed.

Since AGX-329 the writer is `agentplex install`: scripts/install.sh installs
the runtime and the command, then hands the rest of the install to it, so the
bootstrap stages below write the file through the handover. The header names
`agentplex install` as the writer; every other line is what install.sh's
write_environment_file wrote before (captured at 74e9d9e, AGX-326), unchanged.
Captured from the AGX-329 branch, stacked on master c1a4e7a (AGX-328). A
deliberate change to the text re-captures both files here.

Captured on 2026-09-26 from the repository root, with docker, out of the two
bootstrap stages of the Dockerfile at that commit, built with

  COMPOSE_PROJECT_NAME=agx-slot-6 pnpm docker:bootstrap

which builds `bootstrap-check` and `hub-bootstrap-check` from
debian:bookworm-slim
(debian@sha256:3783cc01769c7b2b1b83a5c5ad96c815348e28ed7da68e2e3687004faa906251).

user.env, from hub-bootstrap-check (image
sha256:effef3b1da9b4bbcc1a6be787cd50f14c350927e61a852b46dfb9608411f7a79). That
stage runs, as the unprivileged user alice with HOME=/home/alice,

  AGENTPLEX_PACKAGE=/package bash /install.sh --role=hub --no-setup

which hands over to `agentplex install --role=hub`, and nothing after it
edits the file. bootstrap-check's own per-user file is
not the one taken: the wizard it drives afterwards rewrites the identity line.

  docker run --rm --entrypoint cat agx-slot-6-bootstrap-hub \
    /home/alice/.agentplex/agentplex.env >user.env
  docker run --rm --entrypoint stat agx-slot-6-bootstrap-hub \
    -c '%a %U:%G' /home/alice/.agentplex/agentplex.env
  600 alice:alice

system.env, from bootstrap-check (image
sha256:2d4ebf03db87b0d5cb61d6a6ffa662492d834a27d923a073ae8550da4107d895). That
stage runs, as root,

  AGENTPLEX_PACKAGE=/package bash /install.sh --system --role=hub

which hands over to `agentplex install --system --role=hub`. --system
declines the wizard, and the uninstall that follows leaves the file
where it is, so the finished image holds it as the install wrote it:

  docker run --rm --user root --entrypoint cat agx-slot-6-bootstrap \
    /etc/agentplex/agentplex.env >system.env
  docker run --rm --user root --entrypoint stat agx-slot-6-bootstrap \
    -c '%a %U:%G' /etc/agentplex/agentplex.env
  640 root:agentplex
